## Functional slice

### Render Lab

`tools/render_lab/` is a loopback-only standard-library browser surface around the existing
`scripts/generate.py` entrypoint. It does not duplicate H3 generation mathematics. The validated
surface provides T2V, I2V, and first/last-frame modes; exact image cardinality and anchor mapping;
curated resolution presets revalidated through `resolve_canvas_size`; one child render at a time;
immutable `out/render-lab/run-*` namespaces; input SHA-256 records; raw logs; benchmark, status,
and telemetry records; failed-run preservation; and polling that stops at terminal `succeeded` or
`failed` while leaving the completed preview stable.

### Resolution and image policy

H3 launch geometry is aligned to 32-pixel multiples, including canonical `512x512`. Production
keyframes now use `minimax_h3_mlx.packing.prepare_keyframe_image`, which deterministically resizes
every input to the selected canvas with PIL LANCZOS resampling. The runtime intentionally does not
crop, letterbox, or add dead space. An aspect-mismatched source may be distorted; an aspect-matched
reference is the caller's responsibility.

The vendored upstream reference retains its historical cover-crop helper; that is not the
production policy for this slice.

### Still-image processor repair

The original I2V failure occurred because `AutoProcessor.from_pretrained` eagerly constructed the
Qwen3-VL video processor, whose backend requires torch and torchvision. The repaired property in
`minimax_h3_mlx/text_encoder.py` loads the direct PIL/NumPy backend:

```python
from transformers.models.qwen2_vl.image_processing_pil_qwen2_vl import Qwen2VLImageProcessorPil

Qwen2VLImageProcessorPil.from_pretrained(str(processor_dir), local_files_only=True)
```

`processor_dir` is the text encoder's sibling `processor` directory when present, otherwise the
model directory. `build_request` calls this processor with `return_tensors="np"`, uses
`merge_size**2` for image-pad counts, and preserves per-image `pixel_values` and `image_grid_thw`
order. The `processor` property remains a backward-compatible alias. The still-image path does not
construct a video processor.

Dependency metadata now directly bounds the API-sensitive packages to `mlx-vlm==0.6.9`,
`transformers==5.14.1`, and `Pillow>=10.3,<16`. The current `.venv` matches those versions. No
clean reinstall was performed; the declaration is the reproducibility repair, not a fresh-install
execution claim.
